### `packages/enterprise/src/core/share.ts` — **P1**

Share namespace. shareID is last-8 of sessionID (predictable from sessionID). secret is crypto.randomUUID() (256 bits). Sync/remove require valid secret. P2 because last-8-of-sessionID is a narrow shareID space, but a strong secret (128 bits) is the actual access control. NOTE: legacy path merges by storage iteration — no auth on legacy data access path. P1 because /api/share/:id/data is auth-free (read) and leaks the entire session including messages/parts/file diffs.

### `packages/enterprise/src/routes/api/[...path].ts` — **P1**

Hono API: POST /share, POST /share/:id/sync (secret required), GET /share/:id/data (NO auth), DELETE /share/:id (secret required). P1 because the GET /data endpoint reads the snapshot with no secret check at all — anyone with a shareID (8 chars from sessionID tail) can read the full session.

### `packages/opencode/src/auth/index.ts` — **P0**

Auth storage: Api/Oauth/WellKnown. Persists to auth.json 0o600. P0: deriveKey() falls back to /etc/machine-id (deterministic, world-readable on Linux) if HOME/.config/dreamcode/auth.key cannot be written. That means on misconfigured deployments, "encrypted" tokens are effectively plaintext to any local process. Also uses require("fs") in ESM context — should fail at runtime in non-CJS bundlers. P1: auth.key path uses process.env.HOME — predictable, not a per-user location.
