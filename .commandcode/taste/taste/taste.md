# Taste
- Highly cost-conscious about LLM API usage in their agent tooling: treats exorbitant token costs as a bug to be fixed, and expects prompt caching, KV cache TTL, and stable presets to be implemented correctly so context is not re-sent and re-billed every request. Confidence: 0.85
- Wants the agent to run `bun` for tests and commands directly without asking for permission first ("run bun, never ask"). Confidence: 0.9
- Prefers a complete-then-build workflow: when a task involves multiple fixes, wants ALL code changes done and verified first, and only then the binary rebuilt — and expects the rebuilt artifact to be checked/verified as ready for usage before the work is reported done. Confidence: 0.8
- Prefers saving substantial work summaries, plans, and handoff docs as files inside the repo (rather than only in chat), and wants the assistant to explicitly name which file they were saved to — this matters for resuming work across model/session switches. Confidence: 0.85
- When asked for a "plan" or handoff, wants thorough, extended, well-structured documentation: full investigation trails, definitive root causes, exact fix steps, and copy-paste verification commands — not terse summaries. Confidence: 0.8
- Frequently switches between paid and free/cheaper models based on price (e.g. abandoning a model when its peak-pricing window starts) — so work should be checkpointed into repo files at natural break points, and any plan must be executable by a weaker/free model later. Confidence: 0.8
- Gets impatient with long trial-and-error debugging loops that don't converge; prefers the agent to stop, record what it learned (root cause, dead ends, next step), and hand off rather than keep burning turns on speculative fixes. Confidence: 0.75
- Handoff docs should combine BOTH a retrospective record of completed/in-progress work AND the forward plan for not-yet-started work in a single resumable file (with status labels like DONE / IN PROGRESS / TODO and a short "how to resume" section). Confidence: 0.7
- Expects debug scaffolding (temp scripts, console.log instrumentation, experimental edits) to be fully cleaned out of the working tree before wrapping up, leaving only the legitimate fixes. Confidence: 0.7
- Uses Pieces LTM as the cross-session memory store: at the start of a session, expects the agent to search Pieces LTM for "what we were working on" and recover context itself instead of asking the user to re-explain. Confidence: 0.85
- Runs their Command Code GUI on top of the kitty terminal (configs under `~/.config/kitty/`), so terminal-side fixes belong in kitty config/keybinds. Confidence: 0.75
- The GUI stack is kitty + zellij: pane/workspace behavior lives in `~/.config/zellij/layouts/*.kdl` and `~/.config/zellij/config.kdl`, launched via a `dev` script in `~/.local/bin`; keep launcher-referenced layout filenames stable and change only their contents. Confidence: 0.7
- Wants minimal terminal GUI layouts: only the panes actually used (e.g. CMDC window + shell), no extra floating/editor panes — and when removing a pane, the replacement should take over its exact size and position. Confidence: 0.75
- Tends to report several distinct bugs plus a layout change in one message (and appends more symptoms mid-investigation) and expects all of them fixed in the same pass. Confidence: 0.7
- Describes bugs informally, symptom-first ("the color keybinds give errors", "clicking fullscreen doesn't work"), and expects the agent to locate the responsible config/root cause itself rather than asking clarifying questions. Confidence: 0.7
- Uses the mouse in the terminal GUI as well as the keyboard: clicks must reach the pane (including accepting agent permission prompts), and lag/jank/"messy" rendering is treated as a real bug to fix. Confidence: 0.65
- Treats anything that makes the agent get stuck — especially permission prompts that can't be accepted inside the GUI — as a defect to be fixed, not a workflow to live with. Confidence: 0.7
- When the agent pauses or a tool call gets interrupted, replies "keep going" instead of answering questions — wants autonomous continuation through investigation and fixes without check-ins. Confidence: 0.65
